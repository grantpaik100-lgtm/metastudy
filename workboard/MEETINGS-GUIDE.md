# 회의 공간 사용 안내

왼쪽 메뉴의 **회의 → 채팅 / 음성회의**에서 사용합니다. 기존 세 계정으로 로그인하며, 학습자 모델과 구조지도 데이터는 변경하지 않습니다.

## 채팅

표시 이름과 사진은 상단 **내 프로필 · AI 연결**에서 설정합니다. 기존 메시지에도 현재 프로필이 표시되며, 원래 작성자의 계정 ID와 변경 기록은 유지됩니다.

- 일반·기획·개발·피드백 채널에 글, 답글, 파일을 남깁니다. Enter는 전송, Shift+Enter는 줄바꿈입니다.
- 파일은 한 번에 5개, 각각 10MB까지 가능합니다. 큰 자료는 링크로 공유합니다.
- 작업판 항목의 `#spatial/항목ID` 또는 전체 주소를 붙여 관련 기획·UI·코드를 연결합니다.
- 대화는 공유 저장소에 남고, 다른 사람이 나중에 접속해도 볼 수 있습니다. 약 3초 간격으로 새 대화를 확인합니다.

## 음성회의

회의를 선택하면 테이블과 세 좌석이 있는 가상 회의실이 나타납니다. 접속 중인 참여자의 캐릭터·이름·마이크 상태가 좌석에 표시됩니다. 이미지를 등록하지 않으면 프로필 사진이나 이름의 첫 글자가 나타납니다. 업로드한 평면 이미지를 회의실 일러스트에 배치하는 방식이며, 이미지를 입체 캐릭터로 자동 변환하지는 않습니다.

공유 화면은 벽면 스크린에서 실시간으로 보입니다. **공유 화면 크게**를 눌러 내용을 읽고, **회의실로 돌아가기**로 좌석을 다시 볼 수 있습니다. 공유가 끝나면 회의 제목이 스크린에 표시됩니다.

1. 제목을 정하고 회의를 만듭니다. 각자 같은 회의를 선택하고 **통화 입장**을 누릅니다.
2. 마이크 권한을 허용합니다. **화면 공유**에서는 브라우저가 보여주는 창이나 화면을 직접 고릅니다. 한 번에 한 명이 공유합니다.
3. **녹음 시작**을 누르면 참여자 모두에게 녹음 표시가 뜹니다. 각자의 마이크를 20초씩 나눠 서버에 저장합니다.
4. 다른 작업 공간으로 이동해도 통화는 이어집니다. 왼쪽 아래 **통화 중** 표시를 눌러 돌아옵니다.
5. **녹음 중지** 후 저장을 확인하고 나갑니다. **회의 종료**는 다른 참여자의 통화도 끝냅니다.

PC Chrome·Edge가 첫 지원 대상입니다. 카메라 영상과 공유 화면 영상은 녹화하지 않습니다. 화면을 설명할 때 해당 작업판 항목이나 자료 링크를 함께 남겨주세요.

중계 서버(TURN)는 사용하지 않습니다. STUN으로 직접 연결을 시도하므로 회사·학교·호텔 등 일부 네트워크에서는 실패할 수 있습니다. 실제로 서로 다른 네트워크에서의 연결은 세 사람이 한 번 확인해야 합니다. 같은 PC의 세 브라우저 테스트는 이 조건을 대신하지 않습니다.

## 내 이름·사진·캐릭터

1. 상단 **내 프로필 · AI 연결**에서 표시 이름, 프로필 사진, 캐릭터 이미지를 각각 설정하고 **프로필 저장**을 누릅니다. 로그인 아이디와 비밀번호는 바뀌지 않습니다.
2. PNG·JPEG·WebP를 올릴 수 있습니다(원본 10MB 이하). 브라우저에서 최대 512px의 WebP로 줄여 저장합니다. 투명한 캐릭터 이미지는 배경 투명도를 유지합니다. GIF·SVG·움직이는 이미지는 지원하지 않습니다.
3. 등록한 캐릭터가 작업판에 떠 있습니다. 마우스나 손가락으로 끌거나, 캐릭터에 초점을 둔 뒤 방향키로 옮길 수 있습니다. 클릭하면 설정과 **잠시 숨기기**가 나옵니다. 숨긴 뒤에는 **캐릭터 보이기**로 복구합니다.
4. **작업판에 내 캐릭터 띄우기**를 끄면 떠 있는 캐릭터를 표시하지 않습니다. 회의실에서는 등록한 캐릭터를 계속 사용합니다. **캐릭터 지우기 → 저장**은 등록 이미지를 삭제합니다.
5. 이름·이미지는 계정에 저장되어 다른 기기에서도 사용합니다. 임시 숨김과 위치는 이 브라우저에만 남습니다. 팀원 화면은 약 30초 안에 또는 창으로 돌아왔을 때 갱신됩니다.

프로필 이미지와 캐릭터 이미지는 로그인한 작업판 팀원만 조회할 수 있습니다. 서버는 본인 계정의 프로필만 수정하며, 다른 창에서 먼저 변경하면 덮어쓰지 않고 새로고침을 안내합니다. 기존 학습자 DB와 MCP 권한은 그대로 유지합니다.

운영 준비: `cloud/schema.sql` 다음에 `cloud/profiles.sql`을 적용합니다. 별도 음성·이미지 AI API나 외부 그래픽 라이브러리는 추가하지 않았습니다.

## 회의 공간과 회의 기록 삭제

- 회의 공간은 밤 숲속 모닥불 캠핑장이다. 통나무에 둘러앉고, 화면을 공유하면 빔프로젝터가 스크린에 비춘다. 끌거나 좌우 방향키로 둘러보고, 두 번 눌러 원래 시점으로 돌아온다.
- **⛶ 전체 화면**은 브라우저 전체 화면을 쓴다. 지원하지 않는 기기(iPhone 등)에서는 창 가득 채우고 Esc나 같은 버튼으로 돌아온다.
- 회의를 고른 뒤 **회의 기록 삭제**를 누르면 그 회의의 대화·녹음·회의록·요약·첨부 파일·알림이 모두 지워진다. 되돌릴 수 없고, 통화 중인 사람이 있으면 삭제를 거절한다.

## 음성 변환과 요약

- 회의 기록에서 **PC에서 글로 변환**을 누릅니다. 기본은 한국어이며 영어·자동 감지도 선택할 수 있습니다.
- 처음에 약 250MB의 Whisper small 양자화 모델을 내려받고 브라우저에 캐시합니다. 실행 파일 약 22MB는 작업판에서 제공합니다. 이후 캐시가 유지되면 모델을 다시 받지 않습니다.
- 변환은 PC에서 실행됩니다. Hugging Face에는 공개 모델 파일을 요청하며, 음성을 음성인식 API로 보내지 않습니다. 공유 녹음과 변환된 글은 작업판의 비공개 저장소에 저장됩니다.
- 처리하는 동안 작업판을 열어두세요. 중단한 경우 이미 완료해 저장한 조각은 유지되고 다음 실행에서 나머지를 처리합니다.
- 숫자·이름·겹쳐 말한 부분은 잘못 인식할 수 있습니다. 시간 버튼으로 원본을 듣거나 **회의록 직접 수정**을 사용합니다.
- **AI에 보낼 요청 복사**를 눌러 기존 AI에 보내면, MCP로 원문·채팅을 읽고 요약을 저장할 수 있습니다. 회의 종료만으로 AI가 자동 호출되지는 않습니다.
- MCP: `list_meetings`, `get_meeting`, `read_team_chat`, `save_meeting_summary`. 읽기 전용 연결은 요약을 저장할 수 없습니다. 요약은 버전 충돌을 검사하고 변경 이력을 남깁니다.

## 녹음 보관과 알림

- 해당 회의가 만들어진 날부터 **30일** 후 원본 음성을 삭제합니다. 자동 정리는 매일 한국 시간 오전 9시에 실행되어 실제 삭제에는 최대 하루 차이가 날 수 있습니다.
- 삭제 3일 전·하루 전에 작업판 상단 **회의 알림**에 안내합니다. **원본 전체 받기**로 참여자별 녹음을 ZIP 파일로 내려받을 수 있습니다.
- **알림 소리 켜기**를 누르면 작업판이 열려 있는 동안 새 알림에 소리를 냅니다. 브라우저 알림을 허용하면 백그라운드 탭에서도 알릴 수 있습니다. 작업판을 완전히 닫았을 때 푸시 알림을 보내지는 않으며, 다음 접속 때 알림함에서 확인합니다.
- 정리 작업이 지연되어 사전 알림을 만들지 못했다면, 알림을 만든 뒤 최소 하루를 더 기다렸다가 삭제합니다.
- 원본이 삭제되어도 채팅·변환한 회의록·요약·연결 항목은 유지합니다. 아직 글로 변환하지 않은 녹음도 30일 정책이 적용되므로 그 전에 변환하거나 내려받으세요.
- 업로드가 실패한 녹음은 해당 PC의 임시 저장소에 보관하고 재시도합니다. **미전송 녹음** 표시가 사라진 뒤 창을 닫는 것을 권장합니다. 브라우저 강제 종료 시 마지막 녹음 조각은 보존되지 않을 수 있습니다.

## 운영 설정과 파일

`cloud/meetings.sql`을 한 번 적용하고 `node cloud/provision-meetings.mjs`로 비공개 버킷을 준비합니다. Vercel 운영 환경에 임의의 강한 `CRON_SECRET`을 넣습니다. `vercel.json`의 일일 예약 작업이 `/api/meetings/maintenance`를 호출하며 같은 비밀값으로 인증합니다. 이 주소는 일반 로그인이나 인증 없는 요청으로 실행할 수 없습니다.

| 파일 | 역할 |
|---|---|
| `meetings.js`, `meetings.css` | 채팅·회의·알림 화면 |
| `meeting-call.js` | 직접 음성 연결·화면 공유·참여자별 녹음 |
| `meeting-storage.js` | 미전송 녹음 보관·음성 변환 준비·ZIP 내려받기 |
| `speech-worker.js` | 브라우저 음성인식 작업 |
| `vendor/speech/` | 버전이 고정된 공개 음성인식 실행 파일과 라이선스 |
| `cloud/meetings.mjs`, `cloud/meetings.sql` | 인증된 데이터 접근·보관 기간·요약 충돌 검사 |
| `cloud/assets.mjs` | 공개 배포 파일의 허용 목록 |
| `test-meetings.mjs`, `test-speech.mjs` | 브라우저·저장소 통합 검증과 한국어 음성 검증 |

실행 코드는 `prepare-speech.mjs`로 공식 npm 패키지를 내려받아 무결성을 확인한 뒤 복사합니다. 패키지 설치 스크립트는 실행하지 않습니다. UI는 기존 Vanilla JS 구조를 유지합니다. 모델은 공개 저장소의 고정 커밋에서 내려받습니다. 음성인식 실행 파일 추가는 사용자가 승인한 PC 음성 변환 구현에 필요한 범위입니다.

## 검증 기록

Google FLEURS 한국어 test 분할의 첫 세 음성(합계 32.22초)을 실제로 내려받아 브라우저에서 변환했습니다. 기본 모델 선택 시험에서는 공백·문장부호를 제외한 문자 127개 중 편집 거리 5(약 3.9%)였고, 실제 가져오기·저장·재생·변환 경로의 Chrome/Edge 통합 시험에서는 편집 거리 6(약 4.7%)였습니다. 숫자와 단위 표기는 별도 정규화하지 않았습니다. 정제된 낭독 음성 세 개의 결과이며 실제 회의 전체의 정확도를 뜻하지 않습니다. 더 가벼운 base 모델은 한 샘플 뒷부분을 누락해 기본값에서 제외했습니다.

세 임시 계정으로 채팅·답글·파일·직접 음성 연결·공유 화면 수신·녹음·재생을 검증합니다. 시간을 앞당긴 별도 테스트 데이터로 3일 전/하루 전 알림, 원본 삭제, 회의록·요약 유지, MCP 읽기·쓰기 및 충돌 검사를 시험합니다. 운영 세 계정의 비밀번호나 학습 기록은 사용하지 않습니다.
