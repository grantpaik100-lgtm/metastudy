# 작업판(workboard) — 계획 → 학습 → 정리 흐름

로컬 작업판 도구에 넣어 쓰는 파일입니다. 작업판 도구 전체(`index.html`, `styles.css`)는 이 저장소에 없고,
여기에는 **바뀐 파일만** 있습니다.

| 파일 | 내용 |
|---|---|
| `workboard-project.json` | 폰 앱 버전 작업판. 화면 10개 · 연결 15개 · 실험 5개 |
| `workboard-project.chatgpt.json` | 같은 10개 화면을 ChatGPT(MCP) 대화 화면으로 바꾼 작업판. 실험 7개 |
| `workboard-project.study-modes.json` | 「계획 · 학습 · 정리 모드 텍스트 와이어프레임 v0.3」을 옮긴 작업판. H-01 · P-01~06 · L-01~04 · S-01~02 (P-05는 inline/fullscreen, S-02는 위젯/웹으로 나눠 15개 화면) · 연결 22개 · 실험 7개 |
| `workboard-project.web.json` | 웹 화면 6개 (홈 · 과목 대시보드 → 과목 등록 / 과목 계획 → 학습 → 정리 → 근거). **합쳐 불러오기**용 |
| `app.js` | 작업판 앱. 폰 · ChatGPT · 웹 목업, 그리기 도구, 편집 창의 블록 추가 버튼, 합쳐 불러오기, 흐름도 연결선 배치 규칙 |
| `board-ops.js` | 작업판 데이터 규칙(브라우저와 서버가 함께 씀). 화면의 `drawing`(그림), 코멘트(`comment.add/delete/resolve` op) |
| `server.mjs` | 공동 작업 서버. 버전 폴더 API(`/api/versions`, 저장 위치 `data/versions/`) 추가 |

## 적용 방법

1. 서버를 끄고, 작업판 폴더의 `app.js` · `board-ops.js` · `server.mjs`를 이 폴더의 파일로 교체한 뒤 서버를 다시 켭니다.
   `board-ops.js`는 서버도 쓰는 파일이라 서버를 다시 켜야 그림이 저장됩니다. 예전 서버에 그림을 저장하면
   "서버가 예전 board-ops.js를 쓰고 있어서…" 안내가 뜹니다.
2. 서버를 켠 뒤 상단 **불러오기**로 `workboard-project.json`(폰 앱) 또는
   `workboard-project.chatgpt.json`(ChatGPT)을 선택합니다.
   (또는 `node server.mjs --seed workboard-project.json`) 바꾸기 직전 작업판은
   서버의 `data/backups/`에 자동 백업됩니다.

## ChatGPT(MCP) 위젯 목업 만들기

와이어프레임에서 **+ ChatGPT 화면**을 누르거나 화면 **편집** 창을 열면, 정보 블록 아래에
**ChatGPT 블록 추가** 버튼과 실시간 미리보기가 있습니다. 버튼을 누르면 커서 위치에 블록이 들어갑니다.
정보 블록에 아래 머리표가 한 줄이라도 있으면 그 화면은 폰 목업 대신 ChatGPT 대화 화면으로 그려집니다
(와이어프레임 · 흐름도 · 프로토타입 모두).

```text
[틀] 웹                                       ← (선택) ChatGPT 웹(데스크톱) 화면으로. 없으면 모바일
[사용자] 미적분 중간고사 10월 21일이야        ← 사용자 말풍선
[도구] StudyMeta 사용 중                      ← 도구 호출 표시
[AI] 할 일을 정리했어요.                       ← ChatGPT 답변
[inline] 할 일 체크리스트                      ← 위젯 시작: inline · carousel · fullscreen · pip
- [x] 극한의 정의 복습 | AI 제안               ← 항목 | 배지  ([ ] [x] = 체크박스)
-- 한 단계 아래 항목                            ← 위계
[버튼] 학습 시작 | 수정하기                     ← 바로 위 위젯의 버튼
```

| 위젯 | 그려지는 모습 | 설계 경고(주황) |
|---|---|---|
| Inline 카드 | 대화 속 카드 | 버튼 3개 이상, 항목 7개 이상 또는 위계가 깊을 때 |
| Inline 캐러셀 | 옆으로 넘기는 카드 묶음, 카드마다 첫 버튼 | 카드 3개 미만 · 8개 초과, 버튼 2개 이상 |
| Fullscreen | 대화를 덮는 전체 화면, 입력창은 유지 | 한 화면에 2개 이상 |
| PiP | 대화 위에 떠 있는 작은 창 | 한 화면에 2개 이상 |

`board-ops.js`와 서버는 바꾸지 않았습니다. 블록은 기존 정보 블록(sections) 문자열에 들어가므로
팀원과 실시간으로 함께 고칠 수 있고, AI 요청문 복사에도 이 형식 설명이 포함됩니다.

## 웹 목업 만들기

와이어프레임에서 **+ 웹 화면**을 누르면 홈 · 과목 대시보드 초안이 채워진 편집 창이 열립니다.
편집 창의 **웹 블록 추가** 버튼으로 블록을 넣을 수 있고, 아래 머리표가 있으면 브라우저 화면으로 그려집니다.
웹 화면은 흐름도에서 폰 두 칸 너비를 차지합니다.

```text
[web] 홈 · 과목 대시보드           ← 주소창에 보일 페이지 이름
[메뉴] *홈 | 계획 | 학습 | 정리     ← 왼쪽 메뉴 (*는 선택된 메뉴)
[탭] *미적분학 | 일반물리학 | ＋
[제목] 안녕하세요!
[배너] 가장 가까운 시험은 … (D-9)
[카드] 미적분학                    ← 이어지는 [카드]는 격자로 배치
- 중간고사 | D-25
- 중간값 정리 | 도움이 필요해요
[버튼] 과목 열기                   ← 바로 위 블록의 버튼
[목록] 오늘 할 일                  ← 한 줄 전체 목록 ('--'로 하위 항목)
[입력] 과목명 | 미적분학            ← 입력칸
[사이드] 다가오는 시험              ← 오른쪽 패널
```

배지 색은 문구로 정해집니다. 확인 필요(빨강) · 도움이 필요해요(주황) · 복습 추천(파랑) · AI 제안(보라) ·
내가 추가/완료(초록) · D-숫자(검정). 한 카드에 상태 배지가 3개 이상이면 design.md 규칙(카드당 최대 2개) 경고가 뜹니다.

## 그리기 도구

와이어프레임 카드 · 흐름도 화면 · 프로토타입의 **그리기** 버튼, 화면 편집 창의 **✎ 그리기로 이어서 편집**,
또는 **+ 그림 화면**으로 그림판을 엽니다.
도형이 하나라도 있으면 그 화면은 글자 블록 대신 그림으로 그려집니다. 그림을 모두 지우면 원래 목업으로 돌아갑니다.

**이어서 그리기**: 아직 그림이 없는 화면에서 그림판을 열면, 지금 보이는 목업(폰 · ChatGPT · 웹)을
도형으로 옮겨 와서 그 위에 이어서 고칠 수 있습니다. 처음부터 그리고 싶으면 안내줄의 **빈 그림판으로 시작**을 누르세요.
(편집 창에서 **✎ 그리기로 이어서 편집**을 누르면 편집 중인 내용을 먼저 저장하고 바로 옮겨 옵니다.)

| 도구 | 단축키 | 사용법 |
|---|---|---|
| 선택 | V | 도형을 눌러 선택 · 끌어서 이동 · 모서리 손잡이로 크기 조절 |
| 사각형 · 원 · 이미지 자리 | R · O · I | 끌어서 그리기 (클릭만 하면 기본 크기), Shift로 정사각형 · 정원 |
| 선 · 화살표 | L · A | 끌어서 그리기, Shift로 45° 단위 |
| 텍스트 | T | 클릭한 뒤 아래 **글자** 칸에 입력 |

- **여러 개 선택**: Shift+클릭, 빈 곳을 끌어 네모로 감싸기, ⌘/Ctrl+A(전체 선택)
- **복사 · 붙여넣기**: ⌘/Ctrl+C · V · X(잘라내기). 같은 브라우저라면 **다른 화면의 그림판에도** 붙여 넣을 수 있습니다.
- **글자 크기**: 작게(13) · 보통(16) · 크게(24) 버튼, 또는 숫자 칸에 **8~120px**을 직접 입력. A− / A+ 버튼과
  ⌘/Ctrl+Shift+. (크게) · ⌘/Ctrl+Shift+, (작게)로 2px씩 조절. 여러 개를 선택하면 한꺼번에 바뀌고, 사각형·원 안의 글자에도 적용됩니다.
- 선택한 도형에 **글자**(버튼 문구 등) · **색**(선만 · 회색 · 보라 · 검정) · **글자 크기** · **둥근 모서리**를 줄 수 있습니다.
- 복제(⌘/Ctrl+D) · 삭제(Delete) · 맨 앞/맨 뒤 · 되돌리기(⌘/Ctrl+Z) · 다시(⌘/Ctrl+Shift+Z) · 방향키 이동 · 저장(⌘/Ctrl+S)
- ChatGPT 요소는 Apps SDK UI 가이드라인에 맞춰 **앱 표시 → 위젯 → AI 후속 답변** 순서, 위젯 안에는 로고 없음,
  주 버튼은 **브랜드** 색, Inline 카드 버튼 최대 2개, 캐러셀 카드는 이미지 + 버튼 1개, Fullscreen은 왼쪽 위 닫기와 답변 조각으로 구성합니다.
  (PiP 요소 버튼은 뺐습니다. 기존 `[pip]` 글자 블록은 그대로 그려집니다.)
- 틀은 **폰**(390×760) · **웹**(1280×800) · **ChatGPT 모바일**(390×760) · **ChatGPT 웹**(1280×800).
  웹 · ChatGPT 웹 틀 그림은 흐름도에서 폰 두 칸 너비가 됩니다.
- **ChatGPT 틀**은 머리줄 · 입력창(웹은 왼쪽 대화 목록까지)이 고정으로 깔리고, 그 사이 대화 영역에 그립니다.
  왼쪽 **ChatGPT 요소**로 사용자 말풍선 · 도구 호출 · AI 답변 · Inline 카드 · 캐러셀 · PiP · Fullscreen 틀을 한 번에 넣을 수 있습니다.
  (대화 요소는 지금까지 그린 것 아래에 이어 붙고, PiP · Fullscreen은 정해진 자리에 들어갑니다.)
- 큰 도형(카드 등)을 옮기거나 복제하면 **그 안에 들어 있는 도형도 함께** 움직입니다.
- 저장하면 `screen.update` 하나로 팀원에게 바로 반영됩니다. 같은 화면을 다른 팀원이 먼저 저장하면 그림판 위에 안내가 뜨고,
  내가 저장하면 그 화면 그림 전체를 내 것으로 덮어씁니다.

## 버전 폴더

와이어프레임 · 흐름도의 **버전 저장** 버튼(또는 왼쪽 메뉴 **버전 폴더**)을 누르면 지금 작업판 전체
(와이어프레임 · 흐름도 · 코멘트)가 이름을 붙인 폴더로 서버의 `data/versions/`에 저장됩니다. 팀원 모두 같은 목록을 봅니다.

- 폴더의 **와이어프레임 / 흐름도**를 누르면 그때 모습을 **읽기 전용**으로 봅니다. 위쪽 보라색 줄에서 현재 작업판으로 돌아가요.
  보는 동안 팀원이 바꾼 내용은 뒤에서 계속 반영됩니다.
- **되돌리기**는 지금 상태를 '되돌리기 전 자동 저장' 버전으로 먼저 저장한 뒤 작업판 전체를 그 버전으로 바꿉니다.
- 버전 파일은 자동으로 지워지지 않습니다. 필요 없으면 **삭제**하세요.

## PDF 내보내기

**PDF 내보내기**(와이어프레임 · 흐름도 · 버전 폴더)를 누르면 인쇄 창이 열립니다. 대상에서 **PDF로 저장**을 고르세요.
표지(프로젝트 · 날짜 · 화면 목록) → 흐름도 한 장 → 와이어프레임 카드(목적 · 목업 · 코멘트) 순서의 A4 가로 문서입니다.
저장된 버전을 보는 중이면 그 버전이 PDF로 나옵니다.

## 코멘트

와이어프레임 카드의 **그리기 · 편집 · 삭제** 옆 **코멘트** 버튼으로 칸을 엽니다. 이름은 작업판에서 정한 내 이름으로 표시되고,
⌘/Ctrl+Enter로 등록합니다. **해결 / 다시 열기 · 삭제**가 있고, 흐름도 카드에는 해결 안 된 코멘트 수(💬)가 보입니다.
코멘트는 각자 따로 더해져서 여러 명이 동시에 달아도 서로 덮어쓰지 않습니다.

## 합쳐 불러오기

와이어프레임 상단의 **파일 합쳐 불러오기**는 지금 작업판을 지우지 않고, 선택한 JSON의 화면 · 연결 · 실험을
**더합니다**. 화면은 기존 화면들 아래쪽에 놓이고, id가 겹치면 새 id가 붙습니다. 같은 제목의 실험은 건너뜁니다.
(상단의 원래 **불러오기**는 작업판 전체를 바꿉니다.)

## 흐름

```text
[계획] 입력 → (PDF 있으면) 자료 분석 → 할 일 체크리스트 (AI 제안 / 내가 추가 구분)
[학습] 범위 선택(단원·개념) → 학습 진행 ⇄ 계획 열람(상시) → 마무리 감지 → 정리하기
                                      ↑ 조금 더 공부하기 ─────────┘
[정리] 구조화(위계 + 이해 체크) → 상태 보기 ⇄ 근거 보기(State · Evidence)
       ├ 체크 안 한 항목 다시 보기 → 학습 진행
       └ 체크리스트에 반영 → 할 일 체크리스트
```

## 러너 모델과 맞춘 부분

- 정리 1의 이해 체크박스는 Evidence `perceived_understanding`('이해했다'는 응답)으로만 기록하고
  State를 직접 바꾸지 않습니다 (Raw Input ≠ State Update).
- 정리 2의 숫자는 `intervention_response` State가 아니라 도움 관련 관찰(힌트 요청 · 힌트 받고
  해결 · 설명 듣고 해결)의 개수입니다. `intervention_response`는 AGENTS.md / design.md 8-2에서
  학생 비노출로 정해져 있어, 이 State를 숫자로 보여줄지는 실험 `exp-intervention-number`로 남겼습니다.
- 근거 화면은 학생용 라벨만 쓰고, 변화 없는 상태는 '변화 없음'으로 표시합니다.
- 합산 점수는 만들지 않습니다.
