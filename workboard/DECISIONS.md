# 결정 장부

작업판에서 확정한 중요한 결정을 기록한다. 화면의 현재 모습은 코드와 작업판에서 보고, 이 문서에는 **왜 그렇게 정했는지**를 남긴다.

AI와 새 대화를 시작할 때 이 문서를 먼저 읽게 하면 이미 끝난 논의를 반복하거나 확정된 원칙을 임의로 바꾸는 일을 줄일 수 있다.

## 무엇을 기록할까

다음 중 하나에 해당하면 기록한다.

- 여러 화면이나 전체 사용자 흐름에 영향을 주는 결정
- 나중에 바꾸면 데이터, 코드, 카피를 많이 고쳐야 하는 결정
- 팀에서 의견이 갈렸고 선택 이유를 보존해야 하는 결정
- 실험실의 결과를 실제 제품 흐름으로 채택하거나 폐기한 결정
- AI가 다음 작업에서도 반드시 지켜야 하는 제품 원칙

다음은 보통 기록하지 않는다.

- 여백, 글자 크기, 색상처럼 쉽게 되돌릴 수 있는 세부 조정
- 아직 결론이 나지 않은 아이디어
- 단순 버그 수정
- 코드만 보면 이유가 분명한 작은 구현 선택

## 상태

- **제안** — 논의 중이며 아직 작업 기준이 아님
- **확정** — 현재 작업 기준
- **대체됨** — 더 새로운 결정으로 교체됨. 삭제하지 않고 새 결정 번호를 연결
- **폐기** — 검토했지만 채택하지 않음

## 기록 형식

아래 블록을 복사해 사용한다.

```md
## ADR-001 — 결정 제목

- 날짜: YYYY-MM-DD
- 상태: 제안 | 확정 | 대체됨 | 폐기
- 관련 화면: 화면 이름 또는 URL
- 관련 실험: 없으면 생략

### 상황

어떤 문제 때문에 결정이 필요했는가?

### 결정

무엇을 하기로 했는가?

### 이유

왜 이 선택을 했는가? 비교한 다른 선택이 있다면 함께 적는다.

### 영향

어떤 화면, 흐름, 데이터 또는 작업 방식이 이 결정을 따라야 하는가?

### 확인 방법

작업판이나 실제 제품의 어디에서 결정이 반영됐는지 확인할 수 있는가?
```
