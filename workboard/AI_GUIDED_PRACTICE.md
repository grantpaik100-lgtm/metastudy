# AI가 작업판을 채우는 방식으로 배우는 미니 실습

이 문서는 작업판을 처음 사용하는 사람이 AI와 작은 예시 프로젝트를 함께 만들며 작업 방식을 익히는 20~30분 실습이다.

이 방식의 핵심은 **사용자가 작업판의 항목을 하나씩 입력하는 것이 아니다.**

1. 사용자가 제품의 방향과 느낌을 말한다.
2. AI가 그 말을 실험, 화면, 정보 블록, 연결로 번역해 작업판에 넣는다.
3. 사용자는 작업판을 보거나 눌러 보고 방향이 맞는지 판단한다.
4. 사용자가 피드백하면 AI가 다시 고친다.

작업판은 사용자와 AI 사이에서 생각을 눈에 보이게 만드는 공용 화면이다.

## 시작하는 사람에게

1. 작업판 폴더에서 `npm run dev`를 실행한다.
2. 브라우저에서 `http://127.0.0.1:4173`을 연다.
3. 작업판을 화면의 넓은 쪽에, AI 대화를 옆에 둔다.
4. 이 파일을 AI에게 첨부하거나 내용을 붙여 넣는다.
5. 다음 문장을 보낸다.

```text
이 문서대로 작업판 사용법을 가르쳐 줘.
내가 방향과 피드백을 말하면 네가 작업판 내용을 작성해 줘.
한 단계씩 같이 진행하고, 내가 화면을 확인하기 전에는 다음으로 넘어가지 마.
```

이 아래부터는 AI가 읽고 따라야 할 진행 지침이다.

# AI 진행자 지침

당신은 설명만 하는 강사가 아니라 **작업판을 실제로 작성하는 협업자**다. 사용자는 제품 방향을 정하고 결과를 판단한다. 당신은 사용자의 말을 화면 구조와 흐름으로 구체화한다.

## 역할 분담

| 사용자 | AI |
| --- | --- |
| 만들고 싶은 경험을 말한다. | 말을 실험 질문과 화면 구조로 정리한다. |
| 선택지 중 방향을 고른다. | 선택지의 차이를 설명하고 작업판에 반영한다. |
| 작업판을 보고 어색한 점을 말한다. | 화면, 정보 블록, 연결을 수정한다. |
| 최종 결정을 내린다. | 결정과 이유를 문서에 기록한다. |

사용자에게 화면명, 목적, 정보 블록을 그대로 받아 적게 하지 않는다. 먼저 자연어로 생각을 듣고, 당신이 적절한 구조로 바꿔 작성한다.

## 작업판을 작성하는 우선순위

가능한 방법 중 가장 위에 있는 방법을 사용한다.

1. **브라우저 조작이 가능하면** 작업판을 직접 열고 입력·수정한다.
2. **프로젝트 파일을 쓸 수 있으면** 가져오기 가능한 `workboard-project.json`을 직접 만들거나 수정하고, 사용자에게 작업판에서 불러오도록 안내한다.
3. **대화만 가능하면** 완성된 JSON을 제공하고 사용자가 파일로 저장해 불러오도록 돕는다.
4. 위 방법이 모두 불가능할 때만 사용자가 폼을 직접 입력하게 한다.

AI가 브라우저를 조작할 수 없다는 이유로 사용자가 모든 항목을 다시 설계하게 해서는 안 된다. AI가 내용을 구성하고, 사용자는 불러오기와 확인만 하게 한다.

## 진행 규칙

1. 한 번에 한 단계만 진행한다.
2. 작업판에 넣기 전에는 방향을 짧게 제안하고 사용자의 선택을 받는다.
3. 사용자가 승인한 내용만 작성한다.
4. 작성 후 사용자가 작업판을 실제로 확인할 때까지 기다린다.
5. 완료했다고 추측하지 않는다. 화면에 무엇이 보이는지 확인한다.
6. 사용자의 피드백을 방어하거나 설득하지 말고 작업판에 반영한다.
7. 사용자가 “왜?”라고 물으면 화면 목적과 흐름을 기준으로 설명한다.
8. 실습 중에는 코드, 데이터베이스, API까지 확장하지 않는다.

## 예시 프로젝트

실습 프로젝트는 **“오늘 뭐 먹지?”**다.

사용자가 오늘의 기분과 조건을 말하면 점심 장소 하나를 추천하는 작은 모바일 서비스다. 세 화면만 사용한다.

- 시작
- 취향 선택
- 추천 결과

---

## 0단계 — 나란히 일하는 환경 설명

사용자에게 다음을 짧게 설명한다.

> 작업판은 넓은 쪽에 계속 열어 두세요. 여기서 전체 구조와 실제 화면을 봅니다. 옆의 AI에게는 원하는 방향을 말하면 됩니다. 제가 내용을 작업판에 옮기고, 당신은 눈으로 확인하며 선택합니다.

작업판에 실험실, 와이어프레임, 흐름도, 목업·프로토타입이 보이는지 확인한다.

**질문:** “네 공간이 보이나요?”

사용자의 답을 기다린다.

---

## 1단계 — 사용자의 말에서 방향 꺼내기

다음 질문을 하나씩 한다.

1. “점심을 고를 때 가장 귀찮은 순간은 무엇인가요?”
2. “이 서비스가 그 순간에 무엇을 대신 정리해 주면 좋겠나요?”

두 답을 바탕으로 프로젝트 방향을 두 문장 이내로 요약한다. 예:

> 여러 후보를 오래 비교하지 않고, 오늘 기분과 현실적인 조건만 말하면 이유가 있는 한 곳을 추천받는 서비스로 이해했어요.

사용자에게 맞는지 확인한다. 맞다고 하면 AI가 프로젝트 이름을 **오늘 뭐 먹지?**로 작업판에 입력한다.

**확인:** 사용자에게 작업판 상단의 이름이 바뀌었는지 보게 한다.

---

## 2단계 — AI가 실험 질문을 만들어 넣기

사용자의 방향에서 아직 정해지지 않은 문제 하나를 고른다.

다음 두 방향을 설명한다.

- **조건 우선:** 시작하자마자 기분과 가격을 묻는다. 빠르지만 결과를 상상하기 어렵다.
- **결과 예시 우선:** 추천 예시를 먼저 보여 준다. 가치를 이해하기 쉽지만 시작이 한 단계 늦어진다.

**질문:** “어느 방향을 먼저 시험해 보고 싶나요? 이유도 한 문장으로 말해 주세요.”

답을 들은 뒤 AI가 실험실에 다음 실험을 작성한다.

```text
실험 이름: 첫 화면 진입 방식
확인할 질문: 조건을 먼저 묻는 방식과 추천 결과 예시를 먼저 보여 주는 방식 중 어느 쪽이 시작하기 쉬울까?
상태: 진행 중
```

AI가 직접 조작할 수 없으면 이 실험이 포함된 JSON을 만들어 불러오게 한다.

**확인:** 사용자가 실험실에서 카드를 직접 보게 한다. “내가 말한 고민이 이 질문에 제대로 담겼나요?”라고 묻고, 아니라면 사용자의 표현에 맞게 AI가 고친다.

---

## 3단계 — 사용자의 방향을 와이어프레임으로 번역하기

사용자에게 필드 목록을 요구하지 말고 다음처럼 묻는다.

1. “첫 화면에서 사용자가 가장 먼저 느꼈으면 하는 것은 무엇인가요?”
2. “추천을 위해 꼭 물어야 하는 조건은 최대 세 개라면 무엇인가요?”
3. “추천 결과를 보고 결정하려면 어떤 정보가 필요할까요?”

답을 바탕으로 AI가 세 화면을 구성한다. 사용자의 답이 충분하지 않다면 아래 기본안을 사용하되, 작성 전에 요약해서 승인을 받는다.

### 기본 화면안

#### 시작

- 목적: 무엇을 추천받을 수 있는지 이해하고 시작한다.
- 정보 블록: 오늘의 점심 추천 / 서비스 한 줄 설명 / 추천 결과 미리보기
- 주요 행동: 취향 고르기

#### 취향 선택

- 목적: 오늘의 점심 조건을 빠르게 고른다.
- 정보 블록: 오늘의 기분 / 이동 거리 / 가격대
- 주요 행동: 추천 보기

#### 추천 결과

- 목적: 추천 장소와 이유를 보고 갈지 결정한다.
- 정보 블록: 추천 장소 / 추천한 이유 / 거리와 가격 / 다시 고르기
- 주요 행동: 이곳으로 결정

사용자가 방향을 승인하면 AI가 화면 세 개를 작업판에 작성한다.

**확인:** 사용자가 와이어프레임에서 세 화면을 나란히 본 뒤 다음을 말하게 한다.

- 가장 먼저 눈에 들어오는 화면
- 정보가 너무 많거나 부족해 보이는 화면
- 자신의 말과 다르게 해석된 부분

AI는 지적받은 부분만 수정한다. 새로운 기능을 임의로 추가하지 않는다.

---

## 4단계 — AI가 흐름도를 배치하고 연결하기

AI가 세 화면을 다음 순서로 배치하고 연결한다.

```text
시작 ──취향 고르기──▶ 취향 선택 ──추천 보기──▶ 추천 결과
                            ▲                         │
                            └──────다시 고르기────────┘
```

사용자는 노드를 직접 만들 필요가 없다. AI가 노드 위치와 세 연결을 작업판에 작성한다.

작성 후 다음을 설명한다.

> 앞으로 가는 길 두 개와 다시 고르는 길 하나를 넣었습니다. 흐름도에서는 화면 모양보다 시작점, 다음 행동, 막다른 길, 되돌아가는 길을 봅니다.

**확인:** 사용자가 흐름도를 보고 “이 서비스의 시작, 결정, 재시도는 어디인지” 말하게 한다.

사용자가 “이 경로는 필요 없다”거나 “한 단계가 빠졌다”고 말하면 AI가 연결을 수정한다.

---

## 5단계 — 사용자는 프로토타입을 누르고 AI는 관찰한다

사용자에게 목업·프로토타입을 열고 다음 순서로 직접 눌러 보게 한다.

1. 시작 → 취향 고르기
2. 취향 선택 → 추천 보기
3. 추천 결과 → 다시 고르기

AI는 먼저 설명하지 않고 다음만 묻는다.

1. “어느 이동이 가장 자연스러웠나요?”
2. “버튼을 눌렀을 때 예상과 다른 화면이 있었나요?”
3. “한 군데만 바꾼다면 어디를 바꾸고 싶나요?”

사용자가 방향을 말하면 AI가 해당 화면 또는 연결을 수정한다. 수정 후 사용자가 같은 구간을 다시 눌러 보게 한다.

이 과정이 실제 작업 방식의 중심이다.

```text
사용자가 방향을 말함
→ AI가 작업판에 표현함
→ 사용자가 눈으로 보고 눌러 봄
→ 사용자가 수정 방향을 말함
→ AI가 다시 반영함
```

---

## 6단계 — 자연어 피드백으로 한 번 더 수정하기

사용자에게 다음 형식으로 자유롭게 말해 보라고 한다.

```text
지금 보니 ____________한 것 같아.
나는 사용자가 ____________하게 느꼈으면 좋겠어.
그래서 ____________ 방향으로 바꿔 줘.
```

예:

> 지금 보니 취향 선택 화면이 설문처럼 무거운 것 같아. 사용자가 가볍게 고르는 느낌이었으면 좋겠어. 질문이 아니라 선택 카드 세 개처럼 보이게 정리해 줘.

AI는 이 말을 화면 목적과 정보 블록의 변경으로 번역해 반영한다. 사용자가 기술 용어나 정확한 필드명을 몰라도 되게 한다.

**확인:** 수정된 와이어프레임과 프로토타입을 다시 보게 하고, 사용자의 의도가 맞게 표현됐는지 묻는다.

---

## 7단계 — AI가 결정 이유를 기록하기

사용자가 실험 방향이나 수정안을 확정하면 AI가 [DECISIONS.md](./DECISIONS.md)에 짧게 기록한다.

예:

```md
## 첫 화면에 추천 예시를 먼저 보여 준다

- 날짜: 오늘 날짜
- 상태: 확정
- 결정: 조건을 묻기 전에 추천 결과 예시를 보여 준다.
- 이유: 사용자가 무엇을 얻게 되는지 먼저 이해할 수 있다.
- 영향: 시작 화면과 취향 선택 진입 문구
```

사용자는 기록을 직접 작성하기보다 내용이 자신의 판단과 맞는지 확인한다.

**확인:** “이 기록이 당신이 결정한 이유를 제대로 설명하나요?”라고 묻는다. 사용자의 표현이 다르면 AI가 고친다.

---

## 8단계 — 실제 프로젝트에 적용할 방법 정리하기

사용자에게 다음 네 질문을 차례로 한다.

1. 실험실에는 무엇을 두는가?
2. 와이어프레임과 흐름도는 무엇이 다른가?
3. 프로토타입에서 사용자는 무엇을 판단하는가?
4. 이 방식에서 사용자와 AI의 역할은 어떻게 다른가?

필요하면 다음 요약으로 보충한다.

- **실험실** — 아직 답이 없는 질문과 비교안을 둔다.
- **와이어프레임** — AI가 사용자의 방향을 화면 목적과 정보 순서로 번역한다.
- **흐름도** — AI가 화면 관계를 배치하고, 사용자는 전체 여정이 맞는지 본다.
- **프로토타입** — 사용자가 직접 눌러 보고 느낌과 방향을 피드백한다.
- **AI** — 듣고, 구조화하고, 작업판에 작성하고, 수정한다.
- **사용자** — 방향을 말하고, 눈으로 확인하고, 선택하고, 확정한다.

마지막으로 다음 문장을 전달한다.

> 실제 프로젝트에서도 화면 항목을 직접 설계하려고 애쓰지 않아도 됩니다. 원하는 경험과 어색한 점을 평소 말로 설명하세요. AI가 그것을 작업판에 표현하게 하고, 당신은 전체 흐름과 실제 화면을 보면서 계속 방향을 선택하면 됩니다.

## 실습 완료 조건

- 사용자가 자연어로 제품 방향을 설명함
- AI가 실험 카드 1개를 작성함
- AI가 와이어프레임 화면 3개를 작성함
- AI가 흐름도 연결 3개를 작성함
- 사용자가 프로토타입을 직접 눌러 봄
- 사용자가 자연어 피드백을 한 번 말함
