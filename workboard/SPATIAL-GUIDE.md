# StudyMeta 작업판 · 3D 구조 지도

책임: 기획, 사용자 경험, MCP 도구, 백엔드 구현의 관계를 편집하고 추적하는 내부 작업판.
학습자 Evidence/State를 쓰거나 운영 서비스를 변경하지 않는다. 현재 상태: 로컬 구현·회귀 검증.

## 원본과 복원 범위

- 프로그램: Downloads의 `workboard-template 2.zip` (2026-09-25 파일).
- 화면 데이터: `workboard-project (5).json` (2026-09-27 20:54 파일).
- 기존 화면 21개·화면 연결 29개·그림 데이터·요청 데이터를 보존했다.
- ZIP은 9월 25일 버전이다. 9월 27일에 별도로 수정한 작업판 코드까지 완전히 복원한 것은 아니다.
- 원래 다운로드 파일은 변경하지 않았다. 이 폴더는 분리된 작업 복사본이다.
- 최신 그림 정보를 구버전 정규화기가 버리는 문제를 고쳐 보존하고 SVG 미리보기를 제공한다. 도형 직접 편집기는 포함하지 않는다.

## 실행

Node.js 22 이상. npm 패키지 설치나 외부 CDN이 필요 없다.

```powershell
cd workboard
$env:PORT='4175'
# 첫 실행은 시드를 사용하고, 이후에는 저장된 편집을 계속 사용한다.
node server.mjs
```

작업판: `http://127.0.0.1:4175/#spatial`
넓게 보기: `http://127.0.0.1:4175/spatial.html`

`--seed`는 이미 있는 로컬 데이터를 백업하고 시드로 교체한다. 평상시에는 사용하지 않는다.
서버는 루프백 주소에만 바인딩한다. 같은 서버에 접속한 브라우저끼리 SSE로 동기화하며
현재 별도 원격 공동 작업 주소나 로그인·권한 시스템은 구축하지 않았다.

## 사용

1. 왼쪽에서 기능 영역을 선택한다. 선택 노드의 선행·후속 연결은 다른 영역에 있어도 표시한다.
2. 빈 영역 드래그는 회전, Shift 드래그는 이동, 휠·버튼은 확대/축소다. `펼쳐 보기`는 정면 비교다.
3. 노드 또는 선을 선택한다. 키보드로는 세부 항목 목록과 회전·확대 버튼을 사용할 수 있다.
4. 제목·내용·담당자·상태·기획일·구현일·운영일·후속 과제·근거를 편집하고 저장한다.
5. 노드의 상위 노드는 같은 면에서만 지정한다. 순환 위계를 서버에서 거부한다.
6. `배치`를 켜고 노드를 옮기면 해당 면 안의 위치가 저장된다.
7. `＋ 노드`, `＋ 연결`로 구조를 확장한다. 연결 자체에도 노드와 동일한 관리 정보가 있다.
8. `내보내기`는 화면 데이터와 3D 구조를 함께 저장한다. 작업판 상단 `불러오기`로 복원한다.

서버 저장 위치는 `data/board.json`이고 백업과 변경 로그도 `data/`에 있다. Git에는 포함하지 않는다.
동시에 같은 항목을 편집하면 먼저 저장된 버전을 기준으로 늦은 쓰기를 거부한다. 현재 초안은
남으며 `최신 내용 다시 보기`로 서버 내용을 확인한다. 편집자 이름은 표시용이며 인증된 신원이 아니다.

## 초기 연결 데이터의 의미

59개 노드, 63개 관계는 다음 자료를 바탕으로 작성한 **검토 가능한 초기 지도**다.

- 기존 작업판의 와이어프레임 21개.
- `studymeta-backend`의 `33787a1` 코드와 PR #9.
- 해당 저장소의 `docs/phase2-goal-tree.md`, `docs/ui-implementation-map.md`.

18개 파일럿 MCP 도구를 개별 노드로 넣었다. 이전 버전의 모든 서비스·연구 기능을 전수 조사한
인벤토리나 정적 분석으로 자동 추출한 호출 그래프는 아니다. `관련 도구`는 사용자 흐름의 대응이며
반드시 버튼의 직접 호출을 뜻하지 않는다. 원문 코드 링크로 관계를 검토한다.

기획 노드는 개념, 9월 UI 노드는 와이어프레임, 10월 수정 노드는 PR 구현 상태를 나타낸다.
확인되지 않은 담당자·최초 기획일·운영 반영일은 빈칸이다. 커밋 작성자를 제품 담당자로 추정하지 않는다.
`확인된 추가일`은 확인한 문서·구현 스냅샷의 날짜이며 역사상 최초 아이디어 날짜를 보증하지 않는다.

현재 날짜 슬라이더는 확인된 추가일 기준의 존재 여부 필터다. 과거의 모든 필드 값을 재구성하는
버전 재생 기능은 아니다. 편집 이후 변경 전·후 값과 편집자·서버 시각은 항목별 최근 50건 보존한다.
Git/PR 자동 동기화, 전체 프로젝트의 역사 복원, 원격 인증 협업은 후속 작업이다.

## 검증

`node test-spatial.mjs`. Playwright가 이미 설치된 경로는 `PLAYWRIGHT_PATH`로 지정한다.
테스트는 `test-output/` 안의 독립 복사본과 임시 포트에 검증용 서버를 실행한다.
사용 중인 작업판의 저장 데이터는 변경하지 않는다.

검증 대상: 원본 그림 보존, 잘못된 참조·순환 위계 거부, 노드/선 편집, 두 창 동기화,
동시 편집 충돌과 초안 보존, 회전·펼쳐 보기, 추가일 필터, 검색, 내보내기,
작업판 메뉴 연결, 모바일 가로 넘침 및 브라우저 오류.
