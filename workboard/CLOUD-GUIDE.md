# 공동 작업판과 AI 연결

작업판: https://studymeta-workboard.vercel.app/#spatial

MCP 주소: https://studymeta-workboard.vercel.app/mcp

## 로그인과 공동 사용

WORKSPACE의 **할 일**(`/#todos`)에서 Phase → 큰 목표 → 작은 목표를 등록하고 담당자·날짜·상태·메모를 함께 편집한다. **일정 달력**에는 날짜가 있는 할 일과 팀 일정, 창업 일정이 함께 나온다. 날짜·시간은 한국(Asia/Seoul) 기준이며 다른 나라에서 접속해도 같은 날짜로 보인다.

**창업 일정**에는 지원사업·공모전/대회·교육/행사와 공고 링크를 직접 등록한다. **일정 달력 → 일정 추가**에서는 내부 마감·회의·출시 같은 팀 일정도 등록할 수 있다. 자동 공고 수집이나 알림 발송 기능은 포함하지 않는다. 항목의 **공유** 버튼은 로그인한 팀원이 바로 열 수 있는 링크를 복사한다. **보관**하면 달력에서 숨기고 보관함에서 다시 꺼낼 수 있다. 상위 목표를 보관하려면 하위 목표를 먼저 보관하거나 옮긴다.

일정은 약 7초 간격으로 공유 내용을 확인한다. 동시에 같은 항목을 수정하면 먼저 저장된 내용만 반영하고, 다른 편집자의 초안을 남겨 최신 내용과 비교할 수 있도록 안내한다. 항목 편집 창에서 최근 30개 변경 이력을 볼 수 있다.

## 실험실의 투표와 익명 피드백

실험 카드의 **투표 · 익명 피드백**을 연다. 질문과 2~6개 선택지로 투표를 만들고 선택하면 바로 저장된다. 계정당 한 표이며 마감 전에는 변경·취소할 수 있다. 한국 시간으로 마감 시각을 지정하거나 만든 사람이 직접 마감할 수 있다. 화면에는 집계와 본인의 선택만 보이고 개별 투표자 목록은 제공하지 않는다. 약 5초 간격으로 다른 팀원의 결과를 반영한다.

익명 의견은 로그인한 팀원만 남길 수 있지만, 의견 데이터에는 작성자·계정 ID·IP·작성 시각을 저장하지 않는다. 일반 보드의 변경 이력에도 남기지 않는다. 본문에 이름이나 특정 상황을 적으면 팀원이 작성자를 짐작할 수 있으므로 완전한 신원 비식별을 보장하지는 않는다. 작성자 연결이 없으므로 제출 후 본인 수정·삭제는 제공하지 않는다. 순서는 작성 순서가 아니다.

할 일·일정, 투표, 익명 의견은 별도 DB 테이블에 저장되어 기존 보드 JSON 내보내기/가져오기에는 포함되지 않는다. 한 화면의 조회 한도는 일정(보관 포함) 1,000개, 실험별 투표 100개·의견 500개다.

관리자가 생성한 세 계정으로 로그인한다. 이메일은 필요 없다. 각자의 초기 비밀번호는
관리자 PC의 `workboard/private/로그인-안내.txt`에만 있으며 첫 로그인 후 변경한다.
비밀번호를 변경하면 이전 로그인과 AI 연결은 해제된다. 공개 회원가입은 제공하지 않는다.

화면과 AI는 같은 공유 DB를 읽고 쓴다. 화면은 활성 상태에서 약 2.5초마다 변경을 확인하며,
백그라운드에서는 10초 간격이다. 접속자 표시는 약 15초 간격이며 45초간 소식이 없으면 사라진다.
변경이 없으면 전체 보드 대신 버전만 확인한다. 오프라인 편집은 지원하지 않는다.

담당자와 수정자는 별개다. 수정자는 로그인 계정으로 서버가 지정하고, AI 편집은 `이름 · AI`로
표시한다. 노드/선의 동일 버전 충돌은 거절하며 화면 편집 초안은 유지한다. 기존 화면 편집은
작업판 버전이 달라지면 저장을 거절하므로 최신 내용을 확인한 뒤 다시 편집한다.

## 기존 AI에 연결

원격 Streamable HTTP MCP와 OAuth를 지원하는 앱에 위 MCP 주소를 등록한다.
작업판 계정으로 로그인하고, 요청하는 앱과 접근 범위를 확인한 뒤 승인한다.
AI 앱의 계정/요금제/관리자 정책에 따른 외부 MCP 지원 여부는 별도로 확인한다.

Codex CLI 예시:

```powershell
codex mcp add studymeta-workboard --url https://studymeta-workboard.vercel.app/mcp --oauth-resource https://studymeta-workboard.vercel.app/mcp
codex mcp login studymeta-workboard
```

등록 방식 선택을 지원하는 최신 CLI에서 필요한 경우 `--oauth-client-registration dcr`를 사용한다.
현재 서버는 DCR(public client) + PKCE S256을 제공한다. CIMD는 제공하지 않는다.
등록 시 로그인까지 끝났다면 다시 로그인할 필요는 없다. 이미 열린 대화에 새 도구가 나타나지
않으면 Codex를 다시 열거나 새 대화에서 연결된 MCP 도구를 확인한다. 다른 팀원은 각자의
AI 앱에서 같은 MCP 주소를 등록하고 본인 작업판 계정으로 승인한다.

Bearer 토큰 방식의 클라이언트는 작업판의 **계정 · AI 연결**에서 개인 연결 토큰을 생성한다.
토큰은 생성 시 한 번만 표시하고 DB에는 해시만 저장한다. 유효기간은 90일이다.
`Authorization: Bearer <토큰>`으로 전달한다. 계정 화면에서 언제든 해당 연결을 끊을 수 있다.
토큰을 채팅·Git·공유 문서에 붙이지 않는다.

| MCP 도구 | 동작 |
|---|---|
| `get_team_planning` | Phase/목표/일정·담당자·항목 버전 조회 |
| `save_team_plan_item` | 일정/목표 생성·수정·보관. 전체 필드와 현재 버전으로 저장, AI 이력 기록 |
| `get_experiment_discussion` | 실험별 투표 집계·본인 선택·익명 의견 조회. 작성자 정보 없음 |
| `create_experiment_poll` | 실험 투표 생성. 실제 투표·익명 의견 제출은 팀원이 웹에서 직접 진행 |
| `get_workboard` | 네 면과 연결, 지정 항목·연결 관계·버전 조회. `includeScreens`로 기존 화면도 조회 |
| `search_workboard` | 제목·설명·담당자·후속 과제·기능 영역 검색 |
| `update_workboard` | 노드·선·화면 추가/수정. 여러 변경은 하나의 트랜잭션으로 저장 |
| `get_workboard_history` | 작성자·AI 여부·시각·변경 이유와 작업 내용 조회 |

예: “자유학습 노드의 후속 과제에 자료 없는 시작 흐름 검토를 추가해줘.”
AI는 먼저 해당 항목을 읽고 `expectedVersion`과 새 `requestId` UUID로 수정한다.
같은 요청의 네트워크 재시도에는 동일 UUID와 동일 내용을 보낸다. 다른 변경에는 새 UUID를 사용한다.
MCP는 노드·선 삭제나 작업판 전체 교체를 제공하지 않는다. 코드·PR·실제 배포를 변경하지 않으며
사용자가 확정한 내용과 근거만 작업판에 기록한다.

## 동료가 작업판 코드를 수정하기

작업판 로그인은 공유 데이터 편집 권한이다. 코드 공동 개발은 각자의 GitHub 계정으로 한다.
저장소 공동 작업자에게는 코드 읽기·쓰기 권한이 있다. 관리자가
[저장소의 Collaborators 설정](https://github.com/grantpaik100-lgtm/metastudy/settings/access)에서 확인한다.
초대받은 경우 본인이 GitHub에서 초대를 수락한다. 작업판 비밀번호나 다른 사람의 GitHub 계정을 공유할 필요는 없다.

현재 공동 개발의 기준은 `codex/spatial-workboard` 브랜치다.
[최신 작업판 코드](https://github.com/grantpaik100-lgtm/metastudy/tree/codex/spatial-workboard/workboard)는 이 브랜치의 `workboard/` 폴더에 있다.
처음 개발용 복사본을 만들 때 다음 순서로 받는다. Git과 Node.js가 필요하며, 현재 검증 환경은 Node.js 24다.

```sh
git clone --branch codex/spatial-workboard https://github.com/grantpaik100-lgtm/metastudy.git
cd metastudy
git switch -c codex/workboard-your-topic
cd workboard
npm run dev
```

`your-topic`은 작업 내용을 나타내는 고유한 이름으로 바꾼다. AI 개발 도구에서는 복사한 `metastudy` 폴더를 연다.
브라우저의 `http://127.0.0.1:4173`에서 로컬 작업판을 확인한다. 이 기본 실행에는 운영 비밀번호나 서버 키가 필요 없다.
로컬 데이터는 해당 PC에만 저장되며 처음에는 빈 작업판일 수 있다. 지도·화면의 기본 편집은 확인할 수 있지만,
로그인·공유 일정·투표·프로필·회의 등 클라우드 기능의 전체 검증에는 별도 개발 DB와 환경 설정이 필요하다.
운영용 `.env.local`, `private/`, 계정 비밀번호, 연결 토큰을 Git에 올리지 않는다.
클라우드 기능을 수정했다면 PR에 검증이 필요한 범위를 적고, 설정된 검증 환경에서 관련 테스트를 실행한다.

AI에게 시작할 때 전달할 요청 예시:

> 이 저장소의 AGENTS.md와 workboard/CLOUD-GUIDE.md를 읽고 작업판 개발을 도와줘.
> codex/spatial-workboard에서 시작한 내 작업 브랜치를 사용하고, 수정 대상은 workboard/ 안의 코드야.
> 저장소 루트의 index.html은 학습자 모델 데모이므로 수정하지 마.
> 내가 요청한 기능을 구현하고 관련 화면과 저장 동작을 검증해줘.
> 검증하지 못한 부분은 명시하고, 변경 이유와 검증 결과를 담은 PR을 준비해줘.

작업 후 자신의 브랜치를 GitHub에 올리고, **base를 `codex/spatial-workboard`로 지정한 PR**을 만든다.
공유 개발 브랜치의 새 변경을 받을 때는 작성 중인 작업을 먼저 커밋한 뒤 `git fetch origin`과
`git merge origin/codex/spatial-workboard`로 반영한다. 충돌이 있으면 의도를 확인하며 해결한다.
다른 사람의 브랜치를 덮어쓰거나 강제로 푸시하지 않는다.

현재 GitHub 자동 배포는 연결되어 있지 않다. PR을 검토하고 필요한 검증을 마친 뒤 기존 Vercel 프로젝트의
배포 담당자가 반영한다. GitHub 코드 권한만으로 운영 DB나 Vercel 관리 권한이 생기지는 않는다.
`main` 병합은 저장소 지침대로 사용자 승인 후 진행한다.

## 저장과 인증

- 별도 Vercel 프로젝트의 `api/gateway.js`가 웹과 MCP 요청을 처리한다. 외부 AI 모델을 호출하지 않는다.
- 기존 Supabase 프로젝트 안에 전용 `workboard_*` 테이블을 사용한다. 학습자 테이블과 기존 Auth 설정은 변경하지 않는다.
- 각 테이블에 RLS를 켜고 `anon`/`authenticated`의 직접 접근을 차단한다. 서비스 키는 서버 환경변수에만 둔다.
- 비밀번호는 개별 salt의 scrypt 해시, 웹/AI 토큰과 인증 코드는 SHA-256 해시로 저장한다.
- 웹은 HttpOnly/Secure/SameSite 쿠키와 동일 출처 요청 검증을 사용한다. 로그인과 인증 요청 횟수를 제한한다.
- OAuth는 정확한 콜백·resource·scope·PKCE 검증, 5분짜리 일회용 코드, 1시간 접근 토큰,
  30일 회전 갱신 토큰을 사용한다. 갱신 토큰 재사용 시 같은 연결의 토큰을 해제한다.
- 저장 트랜잭션은 보드 행을 잠그고 버전을 검사한다. 별도 항목의 동시 변경은 재조회 후 병합한다.
- 변경 이력에는 수정한 항목의 전후 값을 보존한다. 전체 가져오기를 할 때만 전후 전체 보드를 보존한다.
- 각 항목 화면의 이력은 최근 50건이다. 전체 공동 변경 이력은 DB에 별도로 남는다.

## 운영과 재배포

### 작업판 동기화와 접속 표시

- 메인 화면과 내장 지도는 탭당 한 번의 상태 조회를 공유한다. 지도를 단독으로 열면 그 창이 직접 조회한다.
- 화면에서 작업 중일 때는 요청 완료 후 2.5초 간격으로 확인한다. 입력이나 새 변경이 1분 없으면 10초 간격으로 줄인다.
- 탭이 숨겨지거나 오프라인이면 정기 상태 조회와 작업판 접속 표시 갱신을 멈춘다. 진행 중인 요청 한 건은 완료될 수 있다.
- 다시 보거나 네트워크가 돌아오면 즉시 확인한다. 숨겨진 팀원은 기존 45초 만료 규칙에 따라 작업판 접속 목록에서 빠질 수 있다.
- 다른 메뉴로 이동하면 내장 지도는 갱신 구독을 쉬고 작성 중인 초안을 유지한다. 돌아올 때 공유된 최신 상태를 받는다.
- 통화 연결, 녹음 업로드, 녹음 삭제 예정 알림은 이 중지 규칙과 별개로 계속 동작한다. 다른 브라우저 탭 사이의 조회는 아직 합치지 않는다.
- 저장 직후에는 전체 상태를 다시 받아 같은 탭의 화면에 즉시 전달한다. 동시에 요청한 새로고침은 하나로 합친다.

1. `cloud/schema.sql`, `cloud/meetings.sql`, `cloud/profiles.sql`, `cloud/planning.sql`을 순서대로 대상 Supabase SQL 편집기에서 실행한다. 전용 테이블·함수·회의 파일 저장소만 생성/갱신한다.
2. `.env.example`을 `.env.local`로 복사하고 값을 로컬에서 입력한다.
3. 최초에만 `node cloud/provision.mjs`로 세 계정과 보드를 만든다. 기존 계정/보드는 덮어쓰지 않는다.
4. Vercel 프로젝트의 루트는 이 `workboard/` 디렉터리다. 서버용 환경변수는
   `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `WORKBOARD_URL`, `WORKBOARD_BOARD_ID`다.
   `WORKBOARD_USERNAMES`는 로컬 계정 생성용이며 배포 환경에 필요 없다.
5. `node test-cloud.mjs`, `node test-spatial.mjs`, `node test-profiles.mjs`, `node test-planning.mjs`를 실행하고 `vercel deploy --prod`로 배포한다. 프로필 검증은 별도 계정과 작업판에서 이미지 저장·권한·실제 통화·공유 화면·퇴장 경쟁 상황을 확인하고 정리한다.

배포 파일에는 명시한 `cloud/assets.mjs`의 화면·스타일·스크립트·음성인식 실행 파일와 서버 코드만 포함된다. `private/`, `.env*`, `data/`, 테스트 결과,
초기 작업판 JSON과 SQL 파일은 공개 정적 자산에서 제외한다. Git 자동 배포는 연결하지 않는다.
이 저장소의 학습자 데모 및 다른 Vercel 프로젝트에 영향을 주지 않기 위한 분리다.

로컬에서 클라우드 데이터를 확인하려면 `.env.local`의 `WORKBOARD_URL`을 로컬 주소로 맞춘 뒤
`node cloud/local.mjs`를 실행한다. 호스트별 세션은 공유하지 않는다. 운영 URL 설정은 배포 환경과 맞아야 한다.

## 검증

`node test-sync.mjs`는 메모리 안의 가상 서버와 실제 Chrome 화면으로 요청 횟수, 두 사용자 동기화, 내장 지도 초안 보존,
오프라인·탭 숨김·복귀, 삭제 알림 유지, 느린 요청 중 동시 새로고침을 검증한다. 운영 DB나 계정은 사용하지 않는다.
`$env:TEST_BROWSER='msedge'`로 Edge에서도 실행할 수 있다.

2026-10-23 로컬 가상 서버에서 같은 지도 화면과 브라우저 시계를 사용해 이전 배포 소스와 비교했다.
초기 로딩을 제외한 60초 동안 상태 조회는 화면 표시 시 48→24건, 탭 숨김 시 12→0건이었다.
접속 표시 갱신은 각각 6→3건, 6→0건으로 줄었고 삭제 알림 조회는 분당 1건을 유지했다.
네트워크 지연과 사용 패턴이 다른 운영 환경의 요청 수나 CPU 절감률을 보장하는 수치는 아니다.

`test-planning.mjs`는 별도 세 계정과 보드에서 목표 계층, 일정 공유·달력, 동시 수정 충돌, 투표 변경·마감, 익명 저장 필드, MCP 권한, 모바일 화면을 검증한다. `$env:TEST_BROWSER='msedge'`를 지정하면 Edge로도 실행한다. 테스트 데이터는 종료 시 삭제한다.

`test-cloud.mjs`는 실제 DB 안에 고유 ID의 임시 보드·계정만 만들고 종료 시 그 ID만 정리한다.
운영 보드와 세 실제 계정은 수정하지 않는다. 검증 항목은 비인증 차단, 첫 비밀번호 변경,
CSRF, 동시 수정, 중복 요청, OAuth/PKCE/코드 재사용, 토큰 갱신·해제, MCP 읽기/쓰기,
두 브라우저의 동기화와 초안 보존, 모바일 넘침 및 런타임 오류다.
