# 네 공간과 3D 구조 지도

작업판의 **3D 구조 지도** 아래에 기획·아이디어, UI/UX, MCP, 백엔드가 있습니다.
네 공간은 공유 DB의 같은 노드와 연결선을 사용합니다. 어느 공간에서 수정하든 3D 면과 MCP 조회에 반영됩니다.

| 공간 | 내용 |
| --- | --- |
| 기획·아이디어 | 큰 목표 아래 작은 아이디어를 분해한 위계. 현재 분해 내용은 팀 검토 초안 |
| UI/UX | 실제 파일럿 UI 코드의 가상 실행, 화면별 버튼과 다음 화면 |
| MCP | UI의 직접 도구 호출, 후속 채팅 요청, 서버 핸들러와 반환 경로 |
| 백엔드 | 파일별 함수, 실제 import와 함수 호출, RPC, SQL이 참조하는 테이블 |

## 따라가기

1. UI/UX에서 **자유 학습 시작**을 누릅니다. 가상 세션이 열리고 해당 버튼이 선택됩니다.
2. 아래 연결 경로에 버튼 → `start_study_session` → `PilotService.startSession` → `PilotDataApi.startSession` → DB 함수가 나타납니다.
3. 경로의 함수 이름을 누르면 해당 분야의 항목으로 이동합니다. 오른쪽에서 소속 파일, 소스 버전, 코드 발췌와 GitHub의 해당 줄을 확인합니다.
4. 3D에서는 분야 버튼이나 빈 공간 드래그로 회전합니다. 네 면은 서로 90도 방향으로 배치돼 있습니다. 각 면 안을 스크롤할 수 있습니다. 선택한 관계만 선으로 나타나며 가려진 면의 연결도 아래 목록에서 접근할 수 있습니다.
5. 담당자, 날짜, 후속 과제를 편집해 저장합니다. **구조 정보 편집**에서 파일·함수·UI 선택자·도구 이름 또는 연결 양 끝을 바꿀 수 있습니다. 새 노드에는 상위 노드를 지정해 위계를 만듭니다.

UI 미리보기는 실제 화면 코드를 사용하지만 데이터와 도구 응답은 가상입니다. 실제 학습 DB 저장이나 AI 호출은 없습니다. 자료 분석·AI 정리 결과가 자동 생성되지는 않습니다. 미리보기에서 후속 채팅을 요청하면 해당 단계까지 안내합니다.

## 근거와 한계

- 확인한 제품 소스는 `studymeta-backend`의 `33787a1bfb173151311b914bdb366f3b3f606962`입니다. 코드 확인 표시는 이 버전의 정적 관계를 뜻합니다. 운영 배포나 실행 로그를 확인했다는 뜻이 아닙니다.
- 함수 직접 호출, 파일 import, RPC 이름과 SQL의 직접 테이블 참조를 수집합니다. 모든 동적 호출·외부 의존성까지 자동 추적하는 도구는 아닙니다.
- **정리하기**는 기록 조회 후 AI에 후속 채팅을 보냅니다. UI가 정리 저장 도구를 직접 호출하는 것으로 표시하지 않습니다. AI가 선택할 수 있는 후속 도구는 검토 초안입니다.
- 지도에 기록한 날짜와 실제 기획·구현·운영 날짜는 별개입니다. 확인하지 못한 구현일·운영일·담당자는 비워 두었습니다.
- Git 변경을 실시간으로 자동 반영하지 않습니다. 코드가 바뀌면 소스 버전을 확인하고 관련 항목을 갱신해야 합니다. 기존 팀 편집을 무단으로 덮어쓰지 않습니다.
- 이전 와이어프레임 21개와 기존 노드·연결선은 보존합니다. 이전 UX 초안은 접힌 목록으로 표시합니다.

## 유지보수 파일

- `spatial.html`: 공통 편집기, 검색·기능·날짜 필터, 공유 저장과 충돌 처리
- `spatial-view.js`, `structure.css`: 실제 네 면의 회전, 분야 전환, 연결선과 상세 공간 배치
- `plane-content.js`: 네 분야의 서로 다른 콘텐츠 표현
- `product-ui-preview.html`, `product-preview-bridge.js`: 가상 데이터로 격리한 제품 UI 스냅샷
- `build-structure.mjs`: 명시적으로 지정한 제품 소스에서 구조와 미리보기 생성
- `structure-snapshot.json`: 코드 근거와 안정된 ID를 가진 가져오기 입력. 공개 정적 자산 제외
- `structure-import.mjs`, `cloud/import-structure.mjs`: 기존 항목을 덮어쓰지 않는 검증·추가 작업
- `test-structure.mjs`: 실제 UI 클릭, 네 면 방향, 공유 수정, 모바일, 데이터 보존 검증

새 코드 스냅샷은 `node build-structure.mjs <제품 저장소 경로>`로 생성합니다. 결과를 검토한 뒤 테스트합니다. 클라우드에는 새 필드를 보존하는 서버를 먼저 배포하고 `node cloud/import-structure.mjs`를 실행합니다. 이 명령은 먼저 검증하고 로컬 비공개 백업을 만든 뒤 30개 이하 작업으로 나눠 추가합니다. 이미 존재하는 ID는 건너뛰므로 기존 항목의 소스 갱신은 별도로 검토해 편집해야 합니다.

MCP의 `get_workboard`, `search_workboard`, `update_workboard`, `get_workboard_history`는 그대로 사용합니다. 검색에는 파일 경로·함수·도구 이름이 포함됩니다. 항목 변경은 조회한 `expectedVersion`을 사용합니다. 이는 작업판의 설명·관계를 수정하는 기능이며 제품 코드를 수정하거나 배포하지 않습니다.
